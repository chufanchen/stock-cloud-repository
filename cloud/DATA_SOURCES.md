# 数据接口覆盖与原版 skill 参考

本次核对范围：当前 `cloud/` 运行代码，以及 Documents 原始包中的 `AI进化初始版/skill-premarket-3pick-plan/`。原始脚本未修改、未直接执行；公开接口只做少量只读抽查。网络检查于北京时间 **2026-10-29** 进行，历史榜单指定 **2026-10-28**。

**结论：行情和模拟账本已有运行链路，研究证据仍有缺口。龙虎榜等接口在原版脚本中能找到；财务三表和公司公告没有完整实现。** 本次新增接口审计和方法记忆，尚未把下表中的研究接口接入每日任务或 AI 输入。样本返回成功不代表全市场覆盖、历史可补齐或长期稳定。

## 当前真正提供给 AI 的内容

`ashare_cloud/review.py::evidence` 提供模拟结算、候选/下一日计划、行情覆盖、竞价说明和近期账户结果；`meeting.py` 再加入共享记忆、角色记忆、历史提案与 `meeting_seed.json`。

当前没有向会议注入龙虎榜、财务三表、公司公告、新闻、行业资金流或外围市场数据。因此“巴菲特席位”目前也不能做有财报依据的公司基本面分析。角色名称和模型知识不能替代这些事实输入。

## 原脚本需要修正的问题

1. **历史信息泄漏。** 龙虎榜 `columns=ALL` 返回 `D1_CLOSE_ADJCHRATE`、`D5_CLOSE_ADJCHRATE` 等上榜后表现字段；席位包还带有后续概率/统计字段。研究输入必须采用当时可知字段白名单。当天收盘后才公开的榜单，也不能用于模拟当天盘前决策。
2. **席位重复累计。** `cand_lhb.py` 分别取买榜、卖榜后相加两边 `NET`，同一席位可能重复，统计范围也可能不同。日榜汇总与席位明细分开保留；按日期、原因、统计区间核对，不能随意选择一个原因组代表全部榜单。
3. **日期和分页写死。** 多处日期固定在2026年9月，股票列表和单页大小也固定。应显式传交易日，核对每页、总数、唯一键与服务端日期；没有历史能力的接口不能假装支持历史补跑。
4. **缺失被当作零。** `tagging.py` 把缺少行情池降成空列表再计数，容易得出“0只涨停”。其 `--post` 参数也未构成完整事后更新流程。必须区分未知、成功且为空、部分覆盖和完整结果。
5. **分钟伪装竞价。** `prep_intraday.py` 中插入09:15昨收、将09:30改标09:25的图形处理不得进入成交证据。09:30分钟成交额也不能无条件代替09:25集合竞价额。
6. **口径和规则过期。** 原文存在创业板10%、旧风险警示涨跌幅、固定手数等不同阶段内容，不能整体迁移。云端 `board_limit` 仍有主板 ST 5%的硬编码，需要另行按日期修正并测试；现有筛选排除 ST 并不能替代全市场数据口径维护。本次不改变交易规则或重算旧账。
7. **采集和计算耦合。** 一些脚本导入时就执行请求并写入固定路径，异常直接打印全文，不能作为库直接导入。需拆成有超时、限速、返回校验和安全诊断的适配器。
8. **外围指标错配风险。** `premarket_scan.py` 的阈值命名涉及 Brent，查询却包含纽约原油 CL；还需要处理海外休市及跨时区报价。本次没有使外围 Gate C 自动通过。

涨跌幅规则按交易所生效日期核对，可参见 [上交所2026年交易规则发布](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml) 和 [证监会上海监管局关于7月6日新规的说明](https://www.csrc.gov.cn/shanghai/c105566/c7643909/content.shtml)。北向披露边界参见 [沪深港交易所披露机制调整](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20240412_10753188.shtml)，不能把旧接口名称或非空响应当成口径证明。

## 应当参考的 skill 方法

已在 `meeting_seed.json` 加入该 skill 及相关脚本的原文件 SHA256，并补充人工整理的方法教训：

- 每项事实保留来源、数据时点和可知时间；财报报告期与公告日期分别记录。
- 把事前特征与事后结果分开，保留拒选理由和失败研究；不改写冻结计划。
- 未知、零值、空列表含义不同；没有财报或公告时，角色应明确证据不足。
- 新闻归因、行业分类、公司公告、财报、估值分别建模，避免互相冒充。
- 龙虎榜按原因和统计区间分析，席位数据先去重核验，再谈资金结构。

已有记忆中的 T+1、费用、同口径基准、预先登记假设和否定标准继续保留。旧绩效数字、互相矛盾的策略参数和未经重验的结论没有迁移。

新增方法仅进入之后**首次创建**的会议上下文。已开始/已完成的会议继续使用其冻结输入，更新 seed 不会重写历史会议，也不代表新数据已进入模型。

## 建议接入顺序与运行位置（待实施）

1. **收盘研究证据：** 龙虎榜日榜/席位、三类涨跌停池、行业与题材。利弗莫尔等席位由此讨论市场结构。优先收集全市场小榜单；席位明细按候选与持仓查询，避免逐只扫描全市场。
2. **公司证据：** 为候选和持仓增加公告、业绩预告与财务三表，再支持有依据的基本面复盘。可以优先评估 [巨潮资讯正式披露](https://www.cninfo.com.cn/) 及其 [数据服务平台](https://webapi.cninfo.com.cn/)；本次只确认入口，未验证自动化接口权限、价格或财务字段覆盖。
3. **可复现实验：** 多指数同期基准、外围市场、分钟轨迹及 `pre/post` 特征面板。补充证券主数据和公司行动，按交易日版本化。

每类数据独立设置同口径来源优先级：有权限且字段适用的服务 → 经过验证的公共网页数据 → 同日期归档；最后标记缺失。不可用龙虎榜替代普通资金流、用新闻替代公告、用旧日缓存冒充当天数据。具体供应商优先级待各类适配器验收后确定，不假设 TickFlow 拥有所有研究数据。

所有采集建议统一保留 `source`、`trade_date`、`observed_at`、`published_at`（未知为 null）、`fetched_at`、单位、完整性、状态和证据哈希。历史回放必须确认当时可知；披露时间未知或后来重述的报表不能用于过去的选股判断。限速、有限重试、断点和熔断按来源独立处理，401/403停用来源，429遵守冷却；不轮换同一服务的域名绕过拒绝。

精确时点的竞价/分钟采样放服务器；收盘榜单和公告采集可放服务器或 GitHub Actions。证据归档到私有 R2，AI 读取经过校验的研究事实，Pages 继续展示复盘摘要与来源状态。外部正文视为数据，不能作为模型指令；只向模型发送相关摘要和可追溯引用。

研究数据缺失时应在会议和网页显式标注，可降级完成不依赖该数据的讨论；交易必需行情继续遵守现有完整性门槛。引入新研究数据不会自行解除交易门槛或批准 AI 提案，规则变更仍需独立验证和明确启用。
