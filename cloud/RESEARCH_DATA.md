# 盘后研究数据与多角色输入

默认每日 `run` 在模拟结算及下一交易日计划保存后，采集研究资料，再创建 AI 会议。数据仅用于盘后复盘，不进入交易引擎，不改选股条件、成交、已有计划或研究提案的启用状态。

## 已接入的十类数据

| 类别 | 来源 | 范围与限制 |
|---|---|---|
| 涨停池、炸板池、跌停池 | 东方财富 | 按当日请求；核对返回总数、重复代码；超过单页容量明确有限覆盖 |
| 龙虎榜日榜 | 东方财富数据中心 | 分页核对日期、记录数和上榜原因，字段白名单排除上榜后涨幅 |
| 龙虎榜买卖席位 | 东方财富数据中心 | 只取关注股票中当天上榜的股票；保留原因、统计分组与买卖侧，不叠加两侧净额 |
| 行业资金流 | 东方财富 | 分页、收盘时间戳校验；供应商的“主力”分类不能推断交易者身份 |
| 题材归因 | 同花顺 | 校验日期；标签是供应商编辑观点，不能视为已证实因果 |
| 财经快讯 | 东方财富 | 最近30条中属于采集当日的标题；不是全天新闻全集 |
| 公司公告 | 东方财富公告索引 | 每只关注股票最近90天最多20条标题、披露时间、分类和链接；包含财报/业绩类公告但未读取正文 |
| 财务三表摘要 | 东方财富数据中心 | 每只关注股票、每张表最近两个可用报告期的关键金额；不是完整三表或审计意见 |

这批接口不需要新增密钥，继续使用现有 R2 和 AI 配置。公开网页数据可能变更、限流或在某些运行环境无法访问；实际运行状态会记录，不把接口代码存在当成已经成功取数。

财报记录同时保留报告期和披露日期。无准确披露时刻时，披露当天的报表暂不采用；利润和现金流是报告期累计口径，不能当单季度。接口可能返回重述版本，本版本不据此进行历史选股或回测。

当前未接入：外围市场/宏观、多指数历史基准、个股资金流历史、完整分钟研究面板、证券主数据动态维护、分红除权处理和完整公告正文。这些仍需各自适配与验证，不能用相似数据替代。原版方法审计见 [DATA_SOURCES.md](DATA_SOURCES.md)。

## 各角色实际如何使用

| 角色 | cloud 中的职责 |
|---|---|
| 利弗莫尔 | 冻结规则下的执行与拒单；结合龙虎榜、涨跌停池和题材讨论市场结构 |
| 巴菲特 | 持仓集中与资金风险；核对财报摘要的报告期、现金流和负债；从公告索引提出核读问题 |
| 科斯托拉尼 | 行业资金流、市场涨跌停结构、题材与快讯；宏观和外围数据缺失时明确未知 |
| AI进化 | 提出可证伪研究，检查时间顺序、样本偏差和数据缺口 |
| 最强AI | 审计四席发言的冲突、引用、缺失数据与口径 |
| 主持人 | 汇总共识与分歧，更新共享记忆，产生待验证提案 |

角色配置在 `meeting.json`，会议运行和断点在 `ashare_cloud/meeting.py`，初始方法记忆在 `meeting_seed.json`。所有角色接收同一份有界事实摘要，前四席独立发言；每类数据标注原采集条数、实际展示条数和是否截断。

这些是已迁移的角色职责、方法记忆和会议流程。原版角色目录的独立模拟账户、全部回测和策略程序没有整体迁移；当前仍是一套固定规则账户。

## 配置、优先级与缺失处理

`cloud/research_data.json` 默认：

- `enabled: true`：新会议前采集；可设为 `false`，显式标为关闭。
- 单次预算240秒、最多100个HTTP请求、请求间隔至少1.2秒。
- 最多10只关注股票，依次优先当前持仓、当天持仓/成交/拒单、当天计划及下一日候选。没有相关股票时，席位/公告/财报显示“不适用”，不是失败。
- AI 研究摘要预算20,000字符，每类只取有限样本，优先包含关注股票；原始规范化证据保留在私有状态目录。
- `sources` 是每类数据的来源列表，支持该类别已实现的供应商及 `archive`。已经封存且哈希正确的同日归档优先复用；无归档时按配置尝试在线来源，再明确缺失。目前每类只有一个在线适配器，没有伪装成多供应商覆盖。

401/403/429会停止该供应商本次运行的后续请求；429不立即重试，后续新日期采集再尝试（同日复盘保留归档），且本次不轮换域名绕过拒绝。短暂网络错误/5xx最多两次，连续网络错误熔断；所有请求受总时间、次数和响应大小限制。日志只记录固定状态，不打印响应正文或含凭据的异常。

普通研究源失败会降级为缺失，不撤销已保存的结算，也不降低交易行情完整性门槛。部分接口或展示样本不足会标为“有限覆盖”。

## 归档、补跑和历史边界

北京时间15:10后才进行当日采集。每日定时任务20:37/21:37符合这一窗口；过早手动运行会显式记录研究数据尚未采集，并可能使该次会议冻结缺失状态。

`research/data/YYYY-MM-DD.json` 保存规范化字段、来源、采集时间、覆盖状态与证据哈希；随现有 R2 状态包上传。一次采集结束后封存，包括当时的部分结果和缺失状态。采集中断且尚未封存时，重跑重新采集；每次仍有请求预算，不保证抓取阶段恰好执行一次。

- 同日重跑复用封存证据，不重复抓取或偷偷替换事实。
- 已开始的会议保留原输入；重试只补未完成席位。旧版已经开始的会议不会突然获得新增研究数据。
- 历史日期仅使用已有同日归档；没有归档时标为缺失，不拿当前行情、新闻、公告或重述财报冒充当时可知数据。
- `--skip-ai` 不启动新的研究采集；已有会议和报告继续保留原事实。
- `review` 对尚未开始的当日会议可以采集研究资料，但不采集交易行情、不结算、不改计划。历史 `review` 不在线补研究资料。

封存状态需要后续更正时，应设计独立的修订记录和新研究版本，不直接覆盖已有会议输入。

## 独立检查（不读写账户、R2或AI）

本地在北京时间交易日15:10后运行，使用独立输出目录：

```bash
PYTHONPATH=cloud .venv/bin/python -m ashare_cloud.research_data \
  --state-dir .research-check \
  --symbols 600519,600000
```

股票代码只是接口检查样本。测试会访问公开行情服务；不自动加载 `.cloud.env`，不读取账户，也不发送模型请求。存在缺失类别时退出码为1；“有限覆盖”是有说明的样本范围，不一定是接口故障。使用不同日期时请理解历史归档限制。

GitHub 中可手动运行 **Actions → 研究数据接口检查 → Run workflow**。该工作流不配置任何密钥，独立保存检查附件。每日任务不用改命令，新会议自动走研究采集。

## 网页显示

日报和 AI 会议页面增加“研究数据来源”：类别、来源、状态、采集条数和时间。Pages 只导出明确允许的展示字段，不公开研究归档全文或完整模型输入。模型发言可能引用已提供的公开研究事实。
